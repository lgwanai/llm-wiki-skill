# P1 混库评测

本轮使用新编制的 **13 份合成资料、19 个物理页**，包含三份同名《交接手册》、同一政策的三个生效版本、正式流程与培训沙盒，以及两个容易混淆的场馆。评测前冻结语料与题库。24 道主测题包含 18 道可答题和 6 道无答案题，另有 3 道规则探针。主测含 13 道中文题和 11 道中英混合题。原文和题目由固定种子生成，使用独立 Wiki 走正常 Agent 编译的发布流程。编译页由夹具从原文确定性生成，共用同一套检索与时效排序。 [语料与答案键](corpus.py)

作答复用当前对话的 Agent。每组提供相同题目的独立乱序证据包，提供检索结果和证据编号，作答后再运行评分。不需要独立模型接口、API Key 或外部裁判。两组为同一 Agent、同一对话各答一次，适合诊断具体错误。模型与真实资料上的表现仍需独立验证。

## 日常自动回归

全量 `pytest` 默认运行这组回归。也可以在仓库根目录单独运行 P1。

```bash
python3 -m pytest -q tests/test_p1_mixed_wiki.py tests/test_answer_verification.py
```

直接推送到 `main` 时，GitHub Actions 自动运行 `P1 fixed-answer regression`。在仓库的 Actions 页面查看结果。失败日志逐项列出题号和提示开关，例如 `S06 (hints=off)`。测试结果用于回归诊断，直接推送无需等待检查通过。

测试在临时 Wiki 重建原语料，重新检索规则开启和关闭两组的证据，复用 [原评测答卷](results.json) 的原始措辞并按来源和物理页绑定引用。两组每道可答题都须找齐证据、引用正确并通过产品校验，每道无答案题都须正确拒答。开启时只有 C01、C02 在各自来源出现正确的时段提示，C03 无提示。关闭时 27 道题均无提示。测试按题号报告失败，计时只作记录。

同一命令还检查 40 天和 87 天串字段、切换当天只接受已生效的新版本，以及「禁止」答成「允许」或把「120 天」答成「20 天」时的自动写回门禁。Agent 和 LLM 路径均用固定草稿验证，失败时不新增或改写 Wiki 页面。日常回归无需 API Key。需要重新作答时，按下文的复跑步骤使用当前 Agent，并另存新结果。

两组的同名文件、新旧规则、干扰页分组均为 **7/7** 证据召回和 **7/7** 引用支持。中文题为 **10/10** 证据、**3/3** 正确拒答，中英混合题为 **11/11** 证据、**3/3** 正确拒答。两道第一名失手题均为中英混合题。D01 第一名是生产手册第 1 页，主证据在第 2 页。D05 第一名是供应商演示中的算法，正式验收证据排第二。 [逐题结果](results.json)

证据召回要求返回的前五条中有正确来源、物理页和预设原文片段。引用支持率要求陈述的值、所答字段及引用同时正确。评分独立于产品自己的校验器。拒答率以无答案题为分母，要求不输出猜测并说明缺失信息。检索每组每题计时五轮，缓存预热后交替执行两个配置，主测每组 120 次。Agent 批次时间从打开证据包到保存答卷，包含浏览和提交，适合记录本次运行，不能用于估计模型单题延迟。毫秒级的组间差异不足以判断性能变化。

## 关闭特定问句规则

对照仅在评测进程中关闭 `raw_evidence._deterministic_answer_hints`。其余检索、重排、时效、原文和通用计算能力保持一致。24 道主测题在开启时也未触发该函数的提示。3 道专门的探针在开启时 **3/3 触发且提示进入 Agent 上下文**，关闭时 **0/3**。探针的引用支持率均为 **2/2**，无答案正确拒答均为 **1/1**。 [逐题提示与引用](results.json)

- **C01 潮桥工坊**。原文写周二 **7.40pm** 关门，开启时返回的提示却是枯蒲集市的 **2.15pm**，且提示出现在潮桥工坊的证据块中。Agent 以潮桥原文作答。
- **C03 鹭湾外借台**。原文没有开放时段，开启时同一个 **2.15pm** 提示跟进了鹭湾的证据块。Agent 拒答。关闭后，两道题均没有这条串源提示。
- **C02 枯蒲集市**。提示与原文一致。直接读取原文也能得到同一答案。

这组结果显示已验证的检索与答题收益为零，同时确认了特定问句规则有跨来源注入数值的现象。主测没有触发规则，三道探针只覆盖了工作日关门时间这条规则。

## 校验器误拦截

P1 校验器另行运行在实际引用页上。独立评分判定有充分引用的 18 道主测答案中，产品校验器分别通过 **12/18** 和 **11/18**。这些比较的作答措辞不同，分差不能归因于问句提示开关。最值得跟进的两类误报可以用本次样本复现。 [校验明细](results.json)

- **同段多个数字**。S06 原文同段记录「留存 40 天」和「申诉 87 天」。两组都正确回答 87 天，但校验器匹配到留存项的 40 天并拦截。
- **时点适用性**。T01–T05 引用了对应生效版本。校验器把答案中复述的问题日期当作需要原文逐字出现的日期，或把「当日适用甲版」这种依赖生效区间的判断当成缺少词面支持。

## 复跑

在仓库根目录执行。让当前 Agent 分别根据两个证据包作答，把答卷按包头格式保存为对应的 `packet-a.answers.jsonl` 和 `packet-b.answers.jsonl`。评分前保留冻结的答案键。可选的 `packet-a.seconds.txt` 和 `packet-b.seconds.txt` 用于记录各批的墙钟秒数。

```bash
wikieval_tmp=$(mktemp -d)
python3 evals/p1_mixed_wiki/run.py prepare --workspace "$wikieval_tmp/run"
python3 evals/p1_mixed_wiki/run.py score --workspace "$wikieval_tmp/run" \
  --output "$wikieval_tmp/results.json"
```

如需固定原答卷措辞复验，完成 `prepare` 后直接评分即可。

```bash
python3 evals/p1_mixed_wiki/run.py score --workspace "$wikieval_tmp/run" \
  --replay-baseline evals/p1_mixed_wiki/results.json \
  --output "$wikieval_tmp/results-after-fix.json"
```
